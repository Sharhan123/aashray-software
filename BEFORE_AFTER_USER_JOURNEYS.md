# Before/After User Journeys

Counts below are estimated from actual controls and routes in the inspected source. A “tap/click” is a deliberate navigation/action control. Typing/selecting field contents and scrolling are excluded unless noted. Login, browser/OS prompts, and the final Send tap inside WhatsApp are shown separately. Current counts assume a staff user starts signed in and the target feature is visible/authorized.

## Expected reductions and behavioral changes

- Put reminder and payment beside residents, eliminating a separate lookup in a different module.
- Make the overdue amount/count navigable, eliminating manual reconstruction from charge rows.
- Preserve property scope from property detail through payment, billing, utility and reminder flows.
- Use one server-calculated state for `Due`, `Overdue`, `Cleared`, and `No bill`; the five-calendar-day boundary must be consistent before click counts imply reliable results.
- Make Android receipt print/share directly available from a saved receipt; no client-generated financial receipt data.
